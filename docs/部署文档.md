# 部署文档

本文说明如何将 AI Agent 博客系统部署到生产环境（Linux 服务器示例）。

---

## 1. 环境要求

| 组件 | 版本 |
| --- | --- |
| Node.js | ≥ 18（推荐 18 LTS 或 20 LTS） |
| MySQL | ≥ 8.0（utf8mb4） |
| Redis | ≥ 6（可选，缺失时自动降级为内存缓存） |
| Nginx | 任意较新版本（反向代理 + 静态托管） |

---

## 2. 数据库初始化

```bash
mysql -u root -p < server/sql/init.sql
```

如需重置默认账号密码（或修改后重新回写）：

```bash
cd server
node scripts/initDb.js          # 建库建表 + 种子数据 + 回写 admin/demo 密码
# 可选参数：--force 强制重建表（会清空数据）；--no-seed 仅建表不导种子
node scripts/initDb.js --force
```

---

## 3. 后端部署

### 3.1 安装与配置

```bash
cd server
npm install --production
cp .env.example .env
```

关键环境变量（`server/.env`）：

| 变量 | 说明 |
| --- | --- |
| `PORT` | 服务端口，默认 `3000` |
| `NODE_ENV` | `production` |
| `CORS_ORIGIN` | 前端域名，多个用逗号分隔 |
| `DB_*` | MySQL 连接信息 |
| `REDIS_ENABLED` / `REDIS_*` | Redis 连接；置 `false` 则降级为内存缓存 |
| `JWT_SECRET` | **生产务必改为随机长字符串** |
| `STATIC_BASE_URL` | 上传文件对外访问前缀（通常为后端域名） |
| `AI_PROVIDER` | `mock` / `openai` / `qwen` / `ernie` |
| `OPENAI_*` / `QWEN_*` / `ERNIE_*` | 对应模型 Key 与地址 |

### 3.2 使用 PM2 守护进程

```bash
npm i -g pm2
pm2 start src/server.js --name ai-blog-server
pm2 save
pm2 startup        # 配置开机自启
```

---

## 4. 前端部署

### 4.1 构建

```bash
cd web
npm install
npm run build      # 产物输出到 web/dist
```

### 4.2 Nginx 托管静态资源 + 反向代理

```nginx
server {
    listen 80;
    server_name blog.example.com;

    # 前端静态资源
    root /path/to/web/dist;
    index index.html;

    # 前端路由 history 回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 上传文件代理
    location /uploads/ {
        proxy_pass http://127.0.0.1:3000;
    }

    # Swagger 文档（生产建议加访问限制）
    location /api-docs {
        proxy_pass http://127.0.0.1:3000;
    }
}
```

> 若前端与后端同源部署，前端 `VITE_API_BASE_URL` 可留空，请求走相对路径 `/api`。

## 5. 健康检查与运维

- 健康检查：`GET /api/health` → `{ status: 'ok', uptime, cacheMode, timestamp }`
- 日志：控制台结构化输出（含请求日志、AI 调用日志）；生产建议接 PM2 日志或外部日志收集
- 定时任务：每日 `00:10` 统计快照、`03:00` 清理 90 天日志、`每小时:05` 刷新热门缓存（见 `server/src/jobs`）
- 优雅关闭：进程收到 `SIGINT`/`SIGTERM` 后会停止接收新请求、关闭定时任务与连接池，10s 兜底强退

## 6. 常见问题

1. **Swagger 0 个接口**：Windows 下 `glob` 只识别正斜杠路径，已在 `swagger.js` 中处理；如仍为空，确认 `routes` 下为 `.js` 文件且含 JSDoc 注解。
2. **Redis 未安装**：将 `REDIS_ENABLED=false`，系统自动使用进程内缓存，功能不受影响（仅多实例部署时缓存不共享）。
3. **AI 接口超时**：离线引擎通常秒回；接真实大模型时确认 `AI_TIMEOUT_MS` 足够（默认 60s，前端 AI 接口超时 90s）。
4. **上传失败**：检查 `UPLOAD_DIR` 目录可写、文件大小不超过 `UPLOAD_MAX_SIZE_MB`（默认 5MB）。
